# Lynx 桌面 Bundle 宿主契约

[English](en/desktop-host.md)

Windows/macOS Lynx 实现在 [客户端子仓库](https://github.com/songloft-org/songloft-player-lynx)；主仓库保持 HTTP API 不变，提供 lite 可执行文件、动态端口和可选的父进程退出监测。桌面包已由客户端共享工作流发布，正式签名/公证和最终设备验收仍开放。

宿主以绝对 `-db`、`-music` 路径及 `-port 0 -parent-watch-stdin` 启动匹配架构的后端，工作目录为应用数据目录。后端监听后输出实际端口，宿主还须通过 `/api/v1/health` 才可自动登录。随机管理员凭据使用 `ADMIN_USERNAME/ADMIN_PASSWORD` 环境变量传入，禁止将密码放进命令行或普通日志。音乐目录与数据库、插件、缓存目录分离。Bundle 本地服务按桌面产品约定监听所有网卡并允许局域网访问；UI 显示实际可用的局域网地址，密码只通过凭据库提供给本机自动登录流程。

已选音乐目录不可用时，客户端保留本地模式和原曲库，在登录页提供重试和另选目录。另选目录须等内置后端健康检查通过后才写入偏好。磁盘未连接时不会因保存的登录令牌进入主页，也不会触发数据库迁移恢复提示。音乐目录可以只读，数据库和缓存仍需要各自的可写目录。

`-parent-watch-stdin` 默认关闭，既有服务器和移动绑定行为不变。开启时 stdin 应连接由宿主独占写端的管道。显式退出时宿主先停止播放、插件和网络，再关闭管道；宿主异常结束也会产生 EOF。EOF/读错误与 OS 退出信号共用 15 秒优雅关闭流程。桌面宿主给出 20 秒宽限后才强制结束进程，不应将管道继承给其他子进程。

父管道在应用初始化前开始监听。若宿主在后端初始化或绑定期间退出，后端会先完成 HTTP Server 的监听器注册，再执行优雅关闭，避免关闭先于 Server 创建而留下孤儿服务。

桌面 CI 启动时解析主仓库 `main` 的最新提交，三个架构复用该 SHA 及其 Go 本地替代模块 `pkg/tag` 的 gitlink。完整应用更新应停止后端，备份 SQLite 主文件及残留 WAL/SHM；新后端迁移失败时只能在明确恢复对应备份后运行旧后端，保留失败现场。

回归：`go test ./internal/parentwatch ./internal/app ./internal/config`。客户端另有真实后端扫描、Range、重启持久化与退出检查；它不代替干净目标设备的安装/升级验收。

# 歌单续播与有声书

普通歌单均支持独立续播状态；播放历史仍保存最近播放的歌曲，不能用历史时间推算集内位置。

## 使用方式

- 编辑歌单开启「有声书」，保存为系统 label `audiobook`，不改变 `normal/radio` 类型，不依赖自定义标签名称。
- 没有已存模式时，有声书默认顺序播放、末尾停止；其他普通歌单使用播放器当前模式。已有歌单模式优先，开关有声书不重置模式或位置。
- 「继续播放／继续收听」恢复歌曲、毫秒位置和歌单模式；点列表、搜索结果或历史中的某首歌曲从头播放。
- 搜索仅帮助定位起播点，队列始终使用完整歌单的持久排序。定位上次收听会清空搜索条件。
- 歌曲移出歌单后进度显示失效；歌单删除时状态级联清理。末尾自然结束后显示「已听完」。

## 服务端契约

`GET/PUT/DELETE /api/v1/playlists/{id}/playback-progress` 需要认证，仅支持普通歌单，沿用服务实例共享数据模型。

GET 返回 `song`（可空）、`position_ms`、`play_mode`、`completed`、`invalid`、`version`、`updated_at`；无记录时 version=0。

PUT 接收 `version` 及可选的 `song_id/position_ms/play_mode/completed`。未提供字段保留，模式可独立保存。song_id 必须是当前歌单成员；模式为 order、loop、single、random 或 singlePlay。版本不符返回 409，禁止盲目重试覆盖。DELETE 清除位置并保留模式，递增版本，避免旧请求恢复已清除的位置。

更新歌单的 PUT 请求支持可选布尔字段 `audiobook`，只修改该系统标记，保留其他 labels。内置歌单的既有编辑保护继续生效。

## 保存与兼容

每 5 秒保存正在播放的进度；暂停、seek、切歌、切换歌单及后台事件补充保存。首次加载失败不建立新的已收听位置。客户端串行写入，网络失败的待提交快照保存在本机；下次播放前仅在版本匹配时补交。冲突停止当前会话自动上传，下次明确播放读取最新状态。

旧服务端没有进度端点时，基本播放保持可用；旧播放历史不伪造秒数。浏览器关闭及操作系统杀进程无法保证最后一次上传，周期保存提供兜底。原生后台行为需按平台设备验收。
